## 0. 목표를 측정 가능하게 정의하기

"증권사보다 뛰어나다"는 말은 검증할 수 없으면 의미가 없습니다. 이 설계는 다음 기준으로 우월성을 **측정**합니다.

| 영역 | 증권사 앱(토스·키움·미래에셋 등)의 현실 | ALPHA TERMINAL이 이겨야 하는 지점 | 측정 방법 |
|---|---|---|---|
| 종목 추천 | 인기·거래대금 순위, 애널리스트 의견 요약 | 미국 전 종목을 매일 점수화하고 **과거 성과가 공개된** 추천 | 일별 추천 원장(수정 불가) → 상위 10%의 20·60일 초과수익, 적중률, 최대낙폭을 SPY 대비 공개 |
| 차트 분석 | 지표 표시만 제공, 해석 없음 | 신호마다 "이 종목·이 신호의 과거 성적"을 표시 | 신호별 백테스트 통계(n, 승률, 평균 R, 기대값) |
| 이벤트 | 뉴스 헤드라인 나열 | 공시 원문을 구조화(오퍼링 규모·워런트·계약 금액)하고 **같은 유형 이벤트의 과거 주가 반응**을 제시 | 이벤트 유형별 사건연구(초과수익 분포, 표본 수) |
| 신뢰성 | 근거 불투명 | 모든 숫자에 출처·시각, 모든 판단에 근거 링크 | 근거 없는 숫자 0건 (자동 검사) |

**우리가 이길 수 없는 영역(정직하게 인정):** 실시간 체결 속도, 주문 실행, 레벨2 호가, 유료 라이선스 데이터의 폭. 이 영역은 따라가지 않고 "분석 품질과 검증 가능성"으로 승부합니다.

### 설계 원칙 (GPT식 실패를 막는 규칙)
1. **LLM은 숫자를 만들지 않는다.** 모든 수치는 데이터 파이프라인이 계산하고, LLM은 계산된 값과 공시 원문을 읽고 해석·요약만 한다. 출력의 숫자는 입력에 있던 값인지 자동 검증한다.
2. **확률은 경험적 빈도로만 표시한다.** "상승 확률 73%" 대신 "과거 동일 조건 412건 중 20일 후 SPY 대비 초과수익 58% (95% 신뢰구간 53–63%)".
3. **Point-in-time.** 모든 데이터는 "그 날짜에 실제로 알 수 있었던 값"으로 저장한다(재무는 *제출일* 기준, 신호는 *확정 봉* 기준). 미래 데이터 누수가 있으면 백테스트가 무의미하다.
4. **추천은 기록되고 지워지지 않는다.** 매일의 추천 목록을 불변 원장에 저장하고 성과를 자동 추적한다.
5. **검증되지 않은 기능은 화면에 "실험적" 표시.**

```

  SEC EDGAR ──► │ 공시 실시간 폴링(1분) · XBRL 재무 · 13F/Form 4                    │
  시세 공급자 ─► │ 일봉/분봉 · 전 종목 스냅샷                                          │
  FINRA ──────► │ 공매도 잔고(월 2회) · 일별 공매도 거래량                            │
  openFDA/CT.gov│ FDA 승인 · 임상시험 상태 변경                                       │
                └──────────────┬────────────────────────────────────────────────────┘
                               ▼
     ┌──────────── 저장 ────────────┐        ┌──────────── 계산 (Batch / Stream) ────────────┐
     │ R2  : 원시 시세 Parquet       │◄──────►│ 야간 배치: 피처 → 팩터 → 모델 점수 → 순위        │
     │ Postgres(Supabase):           │        │ 장중 스트림: 신호 감지, 이벤트 분류, 알림         │
     │   종목·피처·점수·신호·이벤트  │        │ 주간: 모델 재학습(walk-forward), 성과 리포트      │
     │   추천 원장·사용자 데이터     │        │ LLM 작업: 공시 구조화 추출, 리서치 요약           │
     └──────────────┬───────────────┘        └───────────────────────────────────────────────┘
                    ▼
     ┌──────────── 서비스 ───────────────────────────────────────────────┐
     │ Cloudflare Workers API (읽기 전용, 캐시)  ·  알림(텔레그램/이메일/웹푸시) │
     └──────────────┬────────────────────────────────────────────────────┘
                    ▼
     React 웹앱 (Cloudflare Pages) — PC 우선, 모바일 대응, PWA
```

### 왜 이렇게 나누는가
- **Cloudflare Worker는 요청당 CPU 시간·서브요청 수 제한**이 있어 전 종목(약 5,000~6,000개 보통주) 계산을 요청 시점에 할 수 없습니다. 현재 V0.3의 "요청 시 계산"은 20종목 수준까지만 가능합니다. → **계산은 배치로 미리 하고, API는 결과를 읽기만** 합니다.
- **배치 실행 위치:** GitHub Actions 크론(무료, 6시간 제한) 또는 Cloudflare Cron + Queues. 1단계는 GitHub Actions(Node로 기존 `packages/analysis` 재사용), ML 재학습은 Python 작업으로 분리.
- **시세 저장:** 6,000종목 × 10년 일봉 ≈ 1,500만 행. Supabase 무료(500MB)에 넣으면 금방 찹니다. 원시 시세는 **Cloudflare R2(Parquet, 종목별 파일)**, Postgres에는 최신 피처·점수만 둡니다.

## 3. 분석 엔진

### 3.1 종목 추천 엔진 (3층 구조)

**1층 — 팩터 점수 (현재 V0.3의 확장)**
- 현재: 종목 하나를 절대 기준(고정 임계값)으로 채점 → **단점: 시장 국면이 바뀌면 기준이 틀어짐.**
- 개선: 전 종목 **횡단면 백분위 순위**로 전환하고, 섹터·시가총액 구간 내 중립화.
- 팩터군 (각각 여러 하위 지표):
  - 모멘텀: 12-1M, 6M, 3M, 52주 고점 근접도, 실적 발표 후 드리프트(PEAD)
  - 품질: ROIC, 매출총이익률 추세, 발생액(accruals), Piotroski F-score
  - 성장: 매출·EPS 성장, 성장 가속도
  - 밸류: EV/EBIT, FCF 수익률, P/S (섹터 내 상대)
  - 수급: 거래대금 증가, 공매도 잔고 변화, 내부자 순매수, 기관 보유 변화(13F)
  - 위험: 변동성, 베타, 희석(주식수 증가·오퍼링 공시), 런웨이, 부채

**2층 — 머신러닝 순위 모델**
- 모델: LightGBM 랭킹 모델. 타깃 = 향후 20거래일 **SPY 대비 초과수익의 횡단면 순위**.
- 검증: **walk-forward**(예: 2016–2020 학습 → 2021 검증 → 한 해씩 전진), 학습·검증 사이 퍼지(purge) 기간을 둬 누수 차단.
- 채택 기준: 상위 10% 포트폴리오가 거래비용 차감 후 모든 검증 구간 평균 초과수익 > 0, 정보계수(IC) 평균 > 0.02, 그리고 1층 단순 팩터 모델보다 우수할 때만 1층을 대체. **못 이기면 단순 모델을 유지**합니다.
- 출력 표시: "상위 X% · 과거 이 분위 종목의 20일 평균 초과수익 Y%, 적중률 Z% (n=…)" — 경험적 수치만.

**3층 — LLM 리서치 (Claude API)**
- 입력: 계산된 피처·점수·이벤트 + 최근 10-Q/8-K 원문 발췌.
- 출력: 투자 논리, 반대 논리, 무효화 조건, 체크리스트. 모든 문장에 근거(피처명 또는 공시 링크) 인용.
- 가드레일: 출력의 모든 숫자를 입력값과 대조, 불일치 시 폐기·재생성. 예측 확률 생성 금지 프롬프트.
- 비용 통제: 상위 100종목 + 관심종목만 매일 생성, 나머지는 요청 시 생성 후 캐시.

### 3.2 차트 분석 엔진

- 현재 V0.3: 지표·구조 신호 계산, 확정 봉 구분 ✅
- 추가:
  - **멀티 타임프레임 합의**: 주봉 추세 + 일봉 구조 + 60분봉 진입 신호 일치도.
  - **신호 성적표**: 각 신호(BOS, CHoCH, FVG 재진입, OB 반응, 이평 돌파, RSI 다이버전스 등)를 전 종목·10년에 걸쳐 백테스트 → 신호 옆에 "이 유형 과거 n건, 승률, 평균 R" 표시. 종목 단독 표본이 30건 미만이면 동일 섹터·변동성 구간으로 보강하고 그 사실을 표시.
  - **자동 레벨**: 거래량 프로파일(분봉 기반 정밀화), 앵커드 VWAP(실적일·갭일 기준), 갭 레벨.
  - **트레이드 플랜 생성**: 진입 구간, ATR 기반 손절, R배수 목표, 포지션 크기(계좌 위험 % 입력 시) — 계산값만 사용.
  - 차트 도구: 그리기 도구(추세선, 피보나치), 레이아웃 저장, 멀티 차트 동기화.

### 3.3 이벤트 레이더 엔진

| 이벤트 | 감지 | 구조화 추출 (LLM + 규칙) | 영향 분석 |
|---|---|---|---|
| 실적 | 8-K Item 2.02, 발표 일정 | 매출·EPS·가이던스 vs 추정치 | 서프라이즈 크기별 과거 반응, PEAD |
| 오퍼링·희석 | S-1/S-3/424B, 8-K 3.02, ATM | 발행 주식수, 가격, 할인율, 워런트 행사가·수량 | 시가총액 대비 희석률, 과거 오퍼링 후 반응 |
| 현금·런웨이 | 10-Q/10-K | 현금, 분기 소진액, going-concern 문구 | 런웨이 < 12개월 경보 |
| FDA·임상 | openFDA, ClinicalTrials.gov, 8-K | PDUFA 일자, 임상 단계·결과 | 바이오 이벤트 유형별 과거 반응 |
| 계약·M&A | 8-K 1.01/2.01, SC TO, DEFM14A | 계약 금액, 상대방, 인수가·프리미엄 | 매출 대비 계약 규모 |
| 내부자·기관 | Form 4, 13D/G, 13F | 매수/매도 금액, 지분 변화 | 클러스터 매수 감지 |
| 공매도 | FINRA | 잔고, 회전일수, 변화율 | 숏스퀴즈 위험 지표 |

- **중요도 = 규칙 기반 점수**(이벤트 유형 × 시가총액 대비 규모 × 과거 반응 크기), 근거 표시.
- **주가 반영 여부**: 발표 시각 이후의 실제 가격·거래량 반응 vs 같은 유형 과거 반응 분포 → "아직 반영 덜 됨 / 과잉 반응 / 평균 수준".
- 각 이벤트에 **SEC 접수 시각(ET), 원문 링크, 우리 시스템 수집 시각** 표시.

## 6. 품질·검증 체계

- **누수 테스트(자동):** 임의 날짜 T로 데이터를 잘라 계산한 값 == 전체 데이터에서 T 시점 값. (V0.3 지표에는 이미 적용됨)
- **데이터 품질 검사:** 결측, 분할·배당 조정 이상치, 가격 점프, 재무 단위 오류 → 실패 시 해당 종목 점수 보류.
- **모델 카드:** 학습 기간, 피처, 검증 성과, 알려진 약점을 문서화하고 화면에서 열람 가능.
- **회귀 테스트:** 고정 스냅샷 데이터로 점수 재현성 검사(CI).
- **LLM 검증:** 출력 숫자-입력 대조, 인용 링크 유효성, 금지 표현(확률·수익 보장) 검사.

## 9. 착수 전 결정이 필요한 항목

1. **Supabase 새 계정** — 생성 후 프로젝트 URL·anon 키 전달 (service_role 키는 GitHub Secrets에만).
2. **Cloudflare 배포 방식** — Pages Git 연동(대시보드에서 5분) 또는 API 토큰.
3. **Alpaca 무료 계정** 생성 → API 키를 Cloudflare/GitHub Secrets에 등록.
4. **2단계 유료 데이터 예산** (월 $0 / ~$100 / ~$200) — P3 이후 결정해도 됨.
5. **Claude API 사용 여부와 월 상한** — P6 전에 결정.
6. **추천 스타일 우선순위** — 중장기(20~60일) 퀀트 vs 단기(1~5일) 이벤트·차트 트레이딩. 둘 다 지원하지만 첫 모델의 타깃 기간을 정해야 함.
